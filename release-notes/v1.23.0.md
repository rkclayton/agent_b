# Agent_b v1.23.0

## A refused delete tells you where to go

Deleting a connection that an agent is using was refused with "assigned to an
agent role" — true, and useless. It now names the agent and every role holding
it, and the message appears on the row you clicked rather than somewhere on the
page. Every role, not the first one, because clearing the one it named and being
refused again is worse than not being told at all.

A delete that is refused, or that names an id which does not exist, now leaves
the configuration exactly as it was. It did not before: the filter rewrote the
live list in place and assigned it before checking whether there was anything to
delete.

## Bold stops being faked

Every bold word in every model answer was the regular typeface smeared wider by
the renderer. The product ships two weights and the browser was asking for a
third that does not exist. It now asks for one that does.

The background texture is half what it was, and the default reading size goes up
one step. If you have already chosen a size, you keep it — this moves where a
reader starts, not what they can pick.

## One waiting indicator, and it says what it is waiting for

There was no general one: a run showed a blinking figure, a queued message
showed a sentence, a model load showed nothing. There is one now, in the
product's own vocabulary, and it cannot be put on screen without a line saying
what is being waited for.

It has two honest modes. When the server actually reports progress — llama.cpp
does, and nothing else this product talks to does — it fills as far as it was
told. When nothing reports, it says so by cycling in place rather than creeping
toward a finish it does not know. A server that stops reporting goes back to
saying it does not know, rather than freezing a bar that will never move.

## Smaller things

- Committed test fixtures no longer carry this machine's name or any real date,
  and a gate now reads what is in the repository — not what the code meant to
  write — and fails on a path, a username, a machine name, an email address or a
  calendar date.
- The two DuckDuckGo search engines are benched with a reason and a date. Both
  answer with an anti-automation challenge instead of results; that is their
  behaviour, not a bug here, and a bench expires and retries where a retirement
  would not.

## Known

The connections page itself is **not** redone in this release, and the model
availability it reports is unchanged. That work depends on a new availability
state, and measuring how it should behave needs a model installed on the Ollama
machine — there are none installed there at the moment, so the measurement could
not be taken and the work was not begun on a guess.
