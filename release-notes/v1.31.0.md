# Agent_b v1.31.0

## Fixed

- With every chat closed, the window went on showing an old chat. Two separate causes: the chat pane could bind itself to a background chat that the tab strip deliberately never shows, and closing the chat you were reading never moved off it. Closing the chat you are in now shows its neighbour; closing the last one shows the empty state, with nothing selected and no message box offered; and a reload lands in the same place instead of back on the transcript you closed.
- A connection could not be removed once any chat had used it, even a chat that was closed. A closed chat keeps a record of which connection it used; it no longer holds a claim on it. Only chats that are open do.
- The "remove this?" question could open off the bottom of the screen when the settings page was scrolled, hundreds of pixels away from the control that raised it. It is placed after the page settles now, against the control it belongs to.
- Long model names in the chat's model switcher were still cut off with an ellipsis. The rule that was meant to stop that was being outranked by a more general one, so it never applied; the name fits whole now.

## Added

- Startup reads each chat's state from a small cached projection instead of re-reading every journal. Measured on a 218 MB set of 33 chats, two of them 56 MB and 48 MB: the step that took 6.2 seconds takes about 50 milliseconds, and a chat you have just used is caught up by reading only what was added to it. The cache holds nothing the journals do not; deleting it costs one slow start.
- An update now says whether it happened. If an install finishes and the running version has not changed — which can happen when something else is still serving the port — that is stated in those words, with the version before and after and the path it was written to. The About row also says how many newer releases exist, and says when update checks are switched off rather than checking silently.
- An edit can carry the checksum of the read it was based on. Every read now begins with the file's checksum, and an edit that sends it back is refused if the file changed underneath — by another chat, by your own editor, or by a command — instead of overwriting work nobody has seen. Sending it is optional.
- Test proposes a name for a connection you have not named, taken from the model it found. A name you have typed is never replaced.
- A message queued while the model was unavailable now keeps its place in the queue across a restart. The message itself was always kept; its position was not.

## Changed

- The automatic progress note no longer asks one summary to be under 400 words, under its token cap, and a verbatim copy of every one of your messages at the same time. Agent_b copies your messages into the note itself, so what you asked for survives, and the model is asked only for the summary. If your messages alone are too large for the window, the note says how much was left out and where to find it.

## Under the hood

- The first of nine end-to-end journeys is written as a release check: add a connection by typing a host, test it, pick a model, save, chat on it, close the chat, remove the connection. It found both connection defects above on its first run.
- The two kinds of log this product keeps are written down: the per-chat journal that is never rotated, and the per-start operational tape that log retention prunes.

## Known

- Every start still appends each chat's whole current state to that chat's own journal, so the journals grow with use — about 0.9 MB per start for the largest chat here. Reading them is no longer the cost it was, and what to do about the writing is recorded for a later release.
- Repair may still fail for a reason particular to your machine; the message and the log it names are what to read if it does.
