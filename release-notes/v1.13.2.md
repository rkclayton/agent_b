# Agent_b v1.13.2

## Updates can install again

v1.13.1 could not be installed through the updater. The updater ran a signature
check and then read the check's answer out of everything the console happened to
print, so a single warning line made a perfectly valid signature look like a
broken one — and the reason was replaced by a parser error. The answer is now
carried in a result file, the check is told to print nothing of its own, and its
three outcomes are kept apart: verified, a bad signature with Windows' own words
for what is wrong, and "the check could not be run" with whatever it did say kept
for the log.

**Install this version by hand, once.** Because the broken code is in the version
already installed, it cannot install its own fix. Download `Agent_b-setup.exe`
from this release page and run it; after that the update button works again.

## A chat is no longer lost to its own size

A server that limits how large a request may be in bytes was refusing sends while
Agent_b, which was counting tokens, believed there was plenty of room — and the
retry sent exactly the same bytes and failed exactly the same way, leaving no
option but to abandon the chat. Agent_b now measures the request it is about to
send, remembers the limit a server names when it refuses one, and shortens the
conversation the same way it does for its token budget until the request fits,
with room to spare. A refusal is acted on once, and a retry is only made when the
request has genuinely become smaller.

## An answer that hits its limit says so, and can be continued

"The run stopped because of length" is gone. A truncated answer now names the
limit it reached, its value, and that it is the connection's own output reserve
setting — and what the model did write is kept in the chat, marked truncated, so
Continue has something to continue from. When thinking used the whole allowance
and left no answer, the stop says that instead, and thinking now gets its own
share of the allowance rather than being able to take all of it. New connections
on a large context get an output reserve proportionate to that context instead of
a fixed 10,240 tokens; saved values are untouched. A connection may also be given
a ceiling in seconds for a single answer, which is off unless you set it.

## Setting up a connection

"Query models" and "Test" are one action. **Test and fill** contacts the address
once, using whatever is typed in the fields — no save first — and then fills the
model list and proposes the context size, output reserve, reasoning cap and effort
as ordinary editable values you can change before saving. It never overwrites
something you typed or saved, so pressing it again is safe. The context size comes
from what the server actually publishes, and where nothing publishes it the value
is marked unverified rather than presented as a measurement.

A new connection no longer carries a model named `model`. It has no model, and
says so. A server that answers but lists no models now says exactly that —
previously it blamed the model name for a server that had nothing loaded.

## Running scripts, and the desktop

`run_script` now resolves a real interpreter and refuses before starting anything
when it cannot find one, naming what to install. A Microsoft Store app-execution
alias — the stub that opens "how do you want to open this file?" and waits — is
refused for that reason, as is an empty file of the same name on PATH. Child
processes get no window and no console of their own. A tool call never waits on a
dialog on your desktop.

## The service-account alarm

With the identity split turned off, nothing tests the service account and no
approval is asked for. The test used to run on every Settings render, which is how
one afternoon produced ten identical approval alarms in four minutes for an
account the product was not using. With the split on and the account unusable, the
alarm appears once per launch and names which condition it is — including which
working directory could not be reached.
