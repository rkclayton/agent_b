# Agent_b v1.20.0

## Settings say whether a change follows you

Every setting now belongs to one of two places: **the machine**, or **the
profile you are in**. Twenty-three top-level settings are classified, and eight
of them follow the profile — your typography, your run limits, your context
thresholds, the reflection floor, your memory, your agents, delivery and
notifications. The Chats, Agents and Notifications pages say so on the page,
once per page rather than once per row.

A page that says nothing is machine-wide, and that absence is the statement: the
listener, the workspace, the service identity, the sandbox, signing, updates and
telemetry are one computer's answers, not one person's, and marking both kinds
would put a note on every row of every page.

**A profile stores only what it disagrees about.** That is what makes a
machine-wide value a default you inherit rather than one you copy: change the
default and it still reaches every profile that never expressed an opinion. A
profile cannot move the listener or turn off the service identity for everyone —
a machine-wide key found in a profile's file is ignored rather than obeyed.

## Runs say why they stopped, in words that exist

Every reason the run loop can end with is now declared, and a test reads the
source to prove it rather than trusting a list. It immediately found one that
was live and undeclared: a turn whose model returned a tool call containing no
calls, twice. Two older reasons, `emergency` and `safe`, have no code left that
emits them; they are recorded as historical, with the recorded sessions that
still carry them named, and such a session still loads and still renders.

## Telemetry sends how big a run was, if you have it on

Two counts join the allow-list: **how many model calls a run made, and how many
tool results came back**. They are counts and nothing else — no tool names, no
model names, no argument content — and they are the same two numbers the
reflection floor reads, taken from the same place, so what was reported and what
the product did cannot disagree.

Telemetry is still off unless you turn it on, and off still means there is no
collector at all.

## Smaller things

- The model file's own parameter count is read when a model is installed, which
  is what a later release will use to choose a reasoning default. An artifact
  that does not carry it, or a connection with no artifact, says **unknown** and
  assumes nothing.
- `agentb`'s documentation gives working one-liners for both install paths and
  says plainly why there is no PATH entry.
- The installer's own test suite had an assertion that failed when a terminal
  was narrow enough to wrap the message it was reading. It no longer depends on
  the width of the window it ran in.

## Known

Switching profiles within a session now restores the machine's defaults before
laying your profile over them. The machine's stored copy of those defaults still
drifts toward whichever profile was last active, so a profile created after a
restart can inherit the last profile's values rather than the original defaults.
The fix needs every write path audited and is not in this release.
