# v1.60.111

- Chats show when a message is queued or when the model is still starting. A failed send returns the message to the composer when the run produced no answer.
- A dropped model response can recover through a bounded retry. Queued messages retain their position in the chat when delivered, and an unreadable saved chat produces one diagnostic until its file changes.
- Scheduled chats use their own workspace, wait up to 30 minutes for a model to start, and retry an unavailable model. Notifications report the final outcome once.
- Small-context chats reserve room for a turn after a large tool result and avoid summarizing the same content repeatedly.
- Tool, thought, and live status rows follow the transcript. Open rows stay in place when new work arrives.
- Invalid connector proposals return validation errors before approval. Stored credentials can match several approved addresses, and a chat can pause while you complete sign-in.
