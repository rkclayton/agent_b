# Agent_b v1.15.0

## A machine can set up the service identity for the people who use it

Agent_b runs shell tools under a separate low-privilege Windows account,
`agentb-svc`, and until now only someone with administrator rights on the machine
could create it. On a managed fleet, where the person using the computer has no
such rights, that left the split either nagging forever or switched off.

A management tool can now do it for them. Run, as SYSTEM:

    provision-service-identity.ps1 -Unattended -ApplicationDirectory <app> `
      -DataDirectory <data> -WorkspaceDirectory <workspace> `
      -ExchangeDirectory <exchange> -ModelAddress <host> -ModelPort <port>

It creates or adopts the account, generates a password nobody types or sees,
applies the folder and firewall policy, verifies the identity by a real Windows
logon, and prints one line of JSON saying what it did. It waits on nothing and
shows nothing. Run it again and it changes nothing, so it is safe on every machine
on every pass. `-RemoveMachineCredential` undoes it.

**Read this before you use it.** To make the credential readable by whoever signs
in to that machine, it is encrypted under a key belonging to the machine rather
than to a person — which means anything running on that machine can decrypt it.
The encryption is therefore not what keeps the password secret; **the file's
permissions are.** Agent_b writes the file readable only by Administrators, SYSTEM
and `agentb-svc`, checks those permissions every single time it reads the file,
and refuses the credential outright if they have been widened. Anyone you put in
the local Administrators group of an endpoint can read that endpoint's service
password. Only the service password may use this scope: connection API keys and
every other stored secret stay encrypted under your own Windows account, and there
is no setting that would change that. The full account is in SECURITY.md.

Your own setup is untouched. If you provisioned the identity yourself, your own
credential is still the one Agent_b uses.

## Text size and typeface for the chat

Settings → Chats has two new rows. **Text size** offers five named steps, from
small to largest; the transcript, the message box and the step rows scale together
and nothing else in the product changes size. **Typeface** offers thirteen faces
by name — the two Agent_b ships and eleven Windows already has — and both settings
take effect the moment you choose them.

Code, tool output and file paths stay monospaced under every typeface, because a
proportional font makes them hard to read.

## Activity uses the width it has

At a wide window Activity left its whole left column empty beside the Lifetime
metrics. Those metrics now spread across the width instead of running down one
column, and the panel above them takes the full width too. Nothing was removed.

Two more places that scrolled inside a page that already scrolls — the status
message on the Security page and the notes on the General page — no longer do.

## An update writes its own records

When a copy of Agent_b updates itself, its install log and progress file now land
beside that copy rather than in your own application data folder. For your own
installation nothing moves; the records are where they have always been.
