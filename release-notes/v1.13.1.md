# Agent_b v1.13.1

## Release notes

Every release now carries a plain-language account of what changed on its GitHub release page. Publication stops if the matching notes file is missing, so a placeholder title can no longer stand in for release notes. v1.13.0 has been backfilled as the first readable entry.

## The window now proves it opened

Launching Agent_b used to report success as soon as the server answered on its port, even when the desktop window failed to appear. The launcher now waits for a visible window, and when one cannot be shown it says why and prints the address you can open in a browser instead.

## Removing a memory note removes it everywhere

Asking Agent_b to forget a note removed it from the stored file, but a chat that was already open could keep carrying it. Removal is now idempotent: the note leaves every open chat as well as the file, and asking again for something already gone is no longer reported as an error.

## Your settings file is left alone

Opening the status page or letting a background probe run could rewrite `harness.json` with identical bytes. Configuration is now saved only when something actually changed, so the file's timestamp reflects real edits.

## Release checks no longer need a copy of your chats

The connection-replay release check compared two rendered copies of the operator's own profile, which made every release depend on a 25-chat data copy and produced false failures when it measured a page before it had drawn anything. It now waits for real chat rows and runs on a small fixture kept in the repository, while still failing on any genuine difference. The production-sized comparison remains available on request.

## Release reliability

The Windows hosted check that inspects service-account status now allows enough bounded startup time for a cold Windows PowerShell process. Slow hosted runners no longer turn that read-only check into a timing lottery.
