# Agent_b v1.29.0

## Fixed

- Repair, under Settings → Security, could not tell you why it failed. The elevated step was started in a way that captures nothing, so whatever it said went to a console nobody sees, and all that reached the screen was that the setup "did not complete". It now runs through a wrapper that keeps every line in the log the message already names, and when the step fails before recording any work the message carries the first thing it actually said.
- A failed Repair was leaving the stored password out of step with the account. A new password is written before the elevated step runs, and it was only put back when you cancelled the prompt or the step never started — not when the step started and failed. Each attempt therefore made signing in less likely to work. It is put back now whenever the step failed without recording any work, and kept when the step recorded work that may already have included the password, in which case you are told to look.
- A long answer spoken back to a phone no longer reads out the markup it was written in, and is cut at a sensible length on a word boundary rather than continuing past the point you can follow.
- A run that stopped is described to a phone in the same words the rest of Agent_b uses, not by its internal name for the reason.

## Added

- The brief a phone asks for now reports which of six states a run is in — queued, running, needs approval, done, failed, stopped — so a shortcut can act on it without reading the spoken sentence, and a link to the chat, which is where an approval has to be answered.
- The chat a spoken request lands in can be chosen under Settings → Chats.

## Changed

- A repeated submission from a phone is matched on its key together with the chat it named. The same key sent against a different chat is a different request, and used to be answered with the first chat's result.
- When Agent_b creates the chat for spoken requests itself, it uses the default connection rather than whichever one happened to be listed first.
- A paired phone speaking the compact message format may now create a chat. It can give the chat a name and nothing else, so it cannot choose which model the chat uses or open a special kind of chat. Everything else that format refuses is unchanged, and what the addition costs is written down in the reference: someone holding a stolen phone can open empty chats, which is visible and reaches no data that was not reachable already.

## Under the hood

- A release check for Repair against a throwaway account is written. It needs an elevated console and an explicit opt-in, because it creates and deletes a local account, and it says so rather than passing quietly when it cannot run.

## Known

- Repair itself may still fail for a reason particular to your machine. What changed is that it can now say which reason; the message and its log are what to read if it does.
- The connections page reports what the connected server says about itself; nothing in this release changes which models a server offers.
