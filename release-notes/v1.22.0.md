# Agent_b v1.22.0

## Numbers stop moving the things next to them

A measured value — how long a run took, what share of it was the model, a median
— changes how many digits it has from one run to the next. Until now every one of
them was laid out at whatever width its current digits needed, so the text beside
it moved, and sometimes the whole column beside it moved.

Every measured value now sits in a seat as wide as the widest form it can take,
with the digits aligned. A number that grows from 50 ms to 103 ms changes the
number and nothing else on the screen.

This was costing more than tidiness. The screenshot comparison that guards every
release had been failing on values rather than on differences for several
releases, and a gate that is already red is a gate a real regression can hide in.
It is green again, and it stays green across two runs that measured different
things — which is the only version of that claim worth making.

## Two gates that were reporting the wrong thing

**A search engine that asks you to wait is not a broken engine.** The capability
suite called `arxiv` FAILING when what actually happened was that its
rate-limit answer took longer to arrive than the eight seconds the suite allows.
It now says it did not find out, which is different from finding out that
something is broken, and a genuine rate limit still benches the engine for as
long as it asked — and, now proven by a test, brings it back afterwards.

**The signing probe refuses to start under the wrong PowerShell** instead of
doing all its work correctly and then failing on the last line. It needs
PowerShell 7; it now says so first, and the test documentation says so where it
tells you to run it.

## The Evaluation Harness sets the reasoning switch

Measuring whether a model should think before it answers was a decision rule
with no loop and a loop with no surface. Both exist now.

The harness runs its ten briefs twice — thinking on, thinking off — and writes
the result onto the connection: reasoning on or off, and a reasoning cap only
when one was actually observed, so a value you set yourself survives a
measurement that could not report one. It shows you both arms side by side, the
one sentence it decided on, and the context window the model will really run
with.

**If a connection has no way to express the switch, the second arm is not run
at all.** Two identical arms would have measured nothing and reported a
difference anyway.

## Known

Nothing new is known-broken in this release. The machine-file drift detection
from v1.21.0 still reports rather than repairs, deliberately: the value drifted
from is unrecoverable, and a guess is worse than telling you where to look.
