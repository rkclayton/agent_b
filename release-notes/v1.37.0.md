# Agent_b v1.37.0

## Changed

- Pairing a phone is now a picture. Settings → Security under "Phone away from home" shows a square code when you press Pair a phone; point the phone's camera at it and tap Pair. The long string of characters is still printed underneath, small, for a phone with no camera, but you no longer type it.
- The square carries the address, the pairing code and this Agent_b's own identity key, so the phone knows which Agent_b it is joining before it connects to anything. The two screens still show the same ten groups of four characters afterwards, and you still compare them before confirming — that step is the one that catches a service in the middle, and nothing replaces it.
- Settings now keeps watch while a pairing is under way. The fingerprint appears when the phone joins, and the paired phone appears when you confirm, without waiting for you to touch anything else.

## Under the hood

- The square is read back rather than looked at: a check decodes the image the same way a camera does — modules, mask, de-interleaved data — from a picture of the actual screen, taken at full width and at the smallest window the frame allows, and compares what it read with what the screen was told to show.
- What the picture carries is then used for real: a stand-in phone, given nothing but the decoded link, pairs with a running Agent_b through the live service and checks that the identity key in the square is the one the service names on the other side.
- The link has one written definition, and a check fails if the document and the code disagree about it. Both values it carries sit in the part of a web address that is never sent to a server, so a phone that opens the link without the app tells nobody anything; it is kept in no file and written to no log.
