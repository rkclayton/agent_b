# Agent_b v1.21.0

## Your settings stay where you put them

Last release gave every setting a scope — the machine's, or the profile you are
in. This one makes every part of the product respect it.

The problem was not in the classification. It was that the configuration a
running Agent_b holds is the machine's values **with your profile laid over
them**, and nineteen different places wrote that whole thing back to the
machine's file. So changing a connection, or turning on the sandbox, quietly
wrote your typography and your run limits into the machine's defaults — and the
next profile you made inherited them as though the machine had always meant
them.

There is now one place that writes the machine's file, and it writes the
machine's own values. A change that belongs to your profile goes to your
profile. The two are no longer able to leak into each other by accident.

**If an earlier build already drifted, Agent_b now says so at startup**, naming
which sections and which profile. It does not repair them: the value they
drifted from is gone, and quietly substituting a default would overwrite
something you may have meant. The message tells you where to look.

## The reasoning switch, measured rather than assumed

The Evaluation Harness decides whether a model should think before it answers.
Until now the rule was written and tested but had never met a model.

It has now, on a 0.8B model: ten briefs with thinking on, ten with it off. With
thinking off, four passed. With thinking on, **none** passed and one turn came
back with no reply at all — no answer, no tool call, after six and a half
seconds of reasoning. That single empty reply is enough to turn reasoning off on
its own, before pass rates are even compared, because a turn that finishes with
nothing is the failure a pass count hides.

The answer for this model is reasoning off, which is what its size alone had
already assumed. One model is not a general result, and it is not claimed as
one.

## Smaller things

- The acceptance suite pins which `git.exe` it uses. Windows installs the same
  program twice and the suite was picking whichever the shell found first, which
  made a screenshot differ by a file path.

## Known

One screenshot comparison still differs, and it is reported rather than hidden.
The Lifetime panel's summary draws a measured duration only when there is one to
draw, which changes how many lines it occupies and moves the column beside it.
Masking the number would not help, and masking what moved would hide real
content. The readout needs to reserve its line; that is a change for the next
release.
