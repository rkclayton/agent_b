# Agent_b v1.33.0

## Fixed

- Repair set up the account, applied every folder protection and then stopped without applying the network policy. The firewall step was calling Windows with a parameter that does not exist, and because that call only runs when the policy is really being applied, every dry run of it passed. It is the right parameter now, and a Repair runs through all three parts.
- When a step like that failed, the reason you were shown was cut off mid-sentence: "A parameter cannot be found that" and nothing more. The rest of it was four lines further down the log and nothing joined them back together. A failure inside the elevated run is now captured whole and shown as one sentence.
- A Repair that only got part of the way says which parts it did: the account and its credential, the folder protections, the network policy, and which one it could not apply and why.
- The window could not be made small. It had never been told what its minimum size was, so it kept Windows' default, and nothing remembered the size you left it at — every launch reopened at 1280 by 860. It now shrinks to 320 by 293, which is one tab, the composer at its shortest and three lines of transcript, and it reopens where and how you left it, small sizes included.

## Under the hood

- The release checks read the hardening scripts and refuse any parameter that the command it is passed to does not have. Seeded with the defect above, it names both lines; the branch that hid it cannot be run without elevation, so reading it is how it gets checked.
- The Repair check asserts that the whole hardening sequence completed, not only that an account was created.
- The acceptance walks the chat surface at the smallest size the window can be dragged to, and asserts nothing runs off an edge, nothing overlaps the composer and the transcript keeps its three lines.
