# Agent_b v1.40.0

## Added

- Agent_b now holds the keys for the services you connect it to. Settings → Security has a Credentials section: give a key a name, the address it belongs to, and paste it once into a masked field. It is never shown again, never appears in a chat, and never reaches the model.
- A connector refers to a key by name instead of carrying one. Nothing in the settings file holds a secret any more, and the model sees only the name.
- Each key is tied to one address — the scheme, the host and the port you approved. It is sent there and nowhere else: not over plain http, not on another port, not to another host, and never carried along a redirect that leaves that address. Those refusals happen before the key is read at all.
- Binding a key to a connector, or moving a bound connector to a different address, asks you first, on the same approval card you already use, naming the key and the exact address.

## Changed

- Keys that used to live in environment variables are moved into the store the first time this version starts. Each one is read, stored, checked by reading it back, and only then is the connector rewritten. If the variable was empty or the check failed, that connector is left without a key and says so, rather than quietly going on using the variable.
- A connector that talks over plain http can no longer carry a key at all.
- A credential helper you supply still works, now with no console window, a hard time limit, and its output held to the same one address.

## Under the hood

- Windows protects each stored key for your account. That protects it at rest and from other users of the machine; it does not hide it from programs running as you, and the security notes now say so in those words.
- A key is planted in tests and then searched for in results, errors and logs; a service that reflects it back has it removed before the answer is shown.
