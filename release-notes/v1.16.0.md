# Agent_b v1.16.0

## A managed install can arrive already pointed at a connection

Deploying Agent_b to a fleet meant installing it and then configuring each
machine by hand. It can now ship configured:

    Agent_b-setup.exe --install --quiet -SeedConfiguration seed.json

The fragment is merged into the configuration **on a first install only**. An
install over a machine somebody is already using preserves everything they have
set and says so in its log — so a redeploy is safe, and re-running it on every
machine on every pass changes nothing it should not. `seed.example.json` ships
with the shape.

**No secrets in a seed.** A fragment carrying an API key, password, token or
client secret is refused at install with the field it found, because the file
lands on every endpoint and credential storage is per-user regardless. Name a
credential *reference* instead and each user supplies the key once. A malformed
or missing fragment fails the install with the reason rather than leaving a
half-configured machine.

The install log names what the seed set, so a NinjaOne run's output shows it.

## The service-identity helper says what happened

Taking **Repair** in Settings → Security could come back with a wall of
`#< CLIXML <Objs …>` and no answer. Those were progress records: Windows
PowerShell serializes them onto the error stream, and Agent_b was reading
anything on that stream as the failure text — so ordinary noise looked like a
failure and the real outcome was lost.

The elevated helper now reports through its exit code and a small result file it
writes. What you see is that file's own message, complete, with the path to the
full output beside it. A cancelled elevation is now its own message — nothing was
attempted, so there is nothing to inspect or repair.

## Agents is one table

Settings → Agents was a picker and a row of bindings. It is now a table with one
row per role: **b** the one you talk to, **c** the worker, **d** the planner when
there is one. Each row carries the role, what it does, and its model. Changing b
here or from the top bar does the same thing. c and d show the model they are
configured with.

The tool toggles are still on the page, behind a fold.

## Activity is quiet until something happens

Activity showed a live run's whole apparatus — the armed detectors, the verdict
chips, the occupancy bar, the Activity and Tools panels — whether or not anything
was running. While idle it is now one line: when the last run ended and what it
cost, with a control to open the detail. A run starting opens it for you. Nothing
was removed; the occupancy bar's labels appear when you point at it.

## The Plan mark is drawn for the size it is drawn at

The mark beside the gear is 12 pixels. It had been prepared at 24 and reduced,
which lost its interior strokes. It is now prepared for each size the product
actually draws it at — 12, 24 and 36 — and your display picks. The Plan page's
full-size artwork is unchanged.

## Ten search results

`web_search` returned five at a time because that was the schema's default and
nothing ever set it. It returns ten.

## Documentation

The shipped documentation was checked against the product as it is. README's
first screen is now what Agent_b is, what it needs, how to install it and how to
reach a first answer; the detail moved to the operator reference. A new test
fails the build on a claim the product no longer supports, so the next rename
cannot leave the documentation behind.
